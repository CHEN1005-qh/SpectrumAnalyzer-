# A · 数据工程改造清单

> 项目：SpectrumAnalyzer（拉曼光谱分析）
> 阶段：方向 A（数据地基）· 只出方案，不写代码
> 依据：基于 `RamanLibrary.db` 的实际盘点结果（参考库 26 条 / 实测库 158 条）

---

## 0. 目标与原则

**目标**：把当前"26 个唯一标签 → 分类退化为检索"的数据，改造成"6 个真实类别、每类多份代表性样本、坐标统一、可训练 + 可独立评估"的监督学习数据集。没有这一步，方向 B（升级真监督学习）无从谈起。

**四条原则**
1. **标签认"物质"，不认"编号"**——`PVC-10` 和 `PVC-13` 是同一类。
2. **数据可追溯**——任何清洗/重采样都保留原始谱，同时导出一份"重建后的规整数据集"。
3. **坐标必须统一**——所有参与训练/预测的谱都落到同一根 X 轴网格上。
4. **预留独立测试**——任何建模前先切出 hold-out 测试集，禁止"用测试集调参"。

## 1. 现状盘点（已实测验证）

### 1.1 参考库 `ReferenceSpectrum`（26 条，天然 6 类）

| 类别 | 样本数 | 统一特性 |
|---|---|---|
| PC | 5 | 全部 1346 点 |
| PE | 5 | X 区间 ≈ 100.9 ~ 3498.4 |
| PET | 5 | PeaksJson 全部存在 |
| PMMA | 2 | 网格基本一致 |
| PP | 5 | |
| PVC | 4 | |

- 问题：标签写成唯一字符串（`PC-Polycarbonate 1`…`PVC-Polyvinyl Chloride 13`），**同类的多条被当成 26 个不同类**。
- 好消息：数据非常规整、无坏点、坐标统一，是理想的"每类代表样本"种子。

### 1.2 实测库 `RamanSpectrum`（158 条，存在 4 类问题）

| 问题 | 具体表现 |
|---|---|
| ① 两套命名体系 | 一部分 `PC-…` / `PE-…`（`-` 分隔，17+17+14+13+24+28 条）；另一部分 `Polycarbonate 1. Clear CD`（`.` 分隔、带物体描述）。 |
| ② 混入异物 | 3 条 `ethanol_spectrum_01_n_n_y` 等，**不属于标准 6 类聚合物**，混入会让分类器出现意外标签。 |
| ③ X 轴网格不统一 | 起点出现 100.9 / 102.5 / 475.9 / 491.0 / 0.0 / 392.4 等 8 种，终点出现 3498 / 3230 / 3080 / 2200 / 2047 / 1998 / 3546 等 7 种——**不能直接喂给 PCA/KNN，维度与语义会对不上**。 |
| ④ 类别不平衡 | PVC≈28、PP≈24、PC≈22、PE≈18(含描述命名)、PET≈19、PMMA≈15，差距约 2×。 |

- 好消息：实测库中有**同一聚合物类下大量真实世界制品**（如 Polycarbonate 的 CD、护目镜、滤壳、LEGO；PVC 的雨衣、线缆护套、玩具 Slinky…），这正是监督学习最需要的"类内多样性"。
- 需要留意：带描述的实测名用 `.` 而非 `-` 分隔，且 **PET 名字含 "Polyethylene"**，聚类时顺序必须"先识 Terephthalate，再识 Polyethylene"，否则 PET 会被误归为 PE。

## 2. 目标数据集形态

归并清洗后，我们要得到一张统一训练表：

```
谱ID | 类别(6类:PC/PE/PET/PMMA/PP/PVC) | 来源(参考/实测) | 原始文件名 | 制品描述 | X_统一轴(1346点) | Y_统一
```

- **6 个类别标签**，不再有编号。
- 每条谱对齐到**统一基准网格**（建议直接沿用参考库的 1346 点网格：约 100.9 ~ 3498 cm⁻¹）。
- 每条谱保留原始谱 + `原始ID/名称/描述` 字段以便追溯。
- 数据导出为 CSV（ID, 类别, 来源, 描述, y1..y1346）用于 Python/SVM/PLS-DA 等建模，同时保留 DB 内规整副本。

## 3. 改造步骤（按序执行）

### 步骤 1 · 建立标准标签体系 + 名称→类别映射规则
- 固化 6 类目标：`PC / PE / PET / PMMA / PP / PVC`，额外保留 `UNKNOWN`（非目标/剔除监测）。
- 建立"物性关键词 → 类别"映射表（顺序敏感）：
  ```
  先匹配  "Terephthalate"            -> PET
  再匹配  "Polymethyl Methacrylate"  -> PMMA  (注意含 "Methyl"，须整词匹配)
  再匹配  "Polyethylene"             -> PE
  再匹配  "Polypropylene"            -> PP
  再匹配  "Polyvinyl Chloride"       -> PVC
  再匹配  "Polycarbonate"            -> PC
  再匹配  "PC-"/"PE-"/… 前缀         -> 对应类
  其余/全部不匹配                    -> UNKNOWN
  ```
- 决策点：以"代码正则映射"自动归一为主，涉及有歧义的少数条目人工复核。

### 步骤 2 · 参考库标签聚合归一
- 把 26 条参考谱按步骤 1 规则归到 6 类，新增/回填 `Category` 字段。
- 验证：PC=5, PE=5, PET=5, PMMA=2, PP=5, PVC=4（与 1.1 一致，无 UNKNOWN）。

### 步骤 3 · 实测库命名规范化 + 清洗
- 对 158 条实测谱套步骤 1 映射，雷同制品（`Polycarbonate 1. Clear CD` 与 `PC-` 前缀）归入同类别。
- **剔除规则（先排除，再人工确认）**：
  - `ethanol*` 3 条 → 移出训练集（除非明显想加乙醇类）；
  - `Name` 为空 / 无法归类的 → 标 `UNKNOWN`，进"待人工标注"区，**不直接进训练**；
  - BLOB 为空或点数少于阈值（如 <100）→ 视为坏谱剔除（当前盘点 0 条，但规则留着防新增）。
- 产出：实测谱类别分布表 + 一份"人工复核名单"（含 3 条 ethanol 与所有 UNKNOWN）。

### 步骤 4 · 统一 X 基准网格 + 全量重采样对齐
- 选定基准轴：**参考库 1346 点网格（≈100.9~3498 cm⁻¹）**，理由：与标准库天然一致、点密度足够。
- 对全部实测谱（起点/终点各异的 158 条）用**线性插值重采样到基准轴**（复用项目已有的 `Resample` / 线性样条逻辑），先做低波数裁剪（复用 `ApplyLowFrequencyCutoff`），负值 clamp 到 0。
- 验证输出：全部谱长度一致（1346）、统计所有谱坐标误差 < 容差。
- 决策点：低波数起点统一裁到多少（建议沿用流程默认 ~200），裁剪后有效点数记为常量。

### 步骤 5 · 类别平衡策略
- 统计归并后的各类样本数，目标"类内≥若干、类间差距可控"。
- 手段（按需选）：
  - **过采样**：对小类（如 PMMA≈15）用已有样本做轻微抖动（加噪/基线偏移/少量平移）生成衍生素谱——注意只在**训练集内**做，测试集用真实谱；
  - **欠采样**：大类（如 PVC≈28）若过量可随机抽齐，或靠类别权重；
  - 记录每次增强的种子，保证可复现。

### 步骤 6 · 划分训练 / 验证 / 测试（hold-out）
- **先切测试集**（建议 ~15–20%，**按类别分层**，保证每类在测试集中都有代表），切后锁定。
- 剩余做训练/验证（用于 KNN 基线调 k、PCA 选主成分数、SVM 的 C/γ 等）。
- 明确分工：
  - `ReferenceSpectrum` 26 条 → 可作为"标准代表"进训练（语义、坐标最干净）；
  - `RamanSpectrum` 实测谱 → 主体训练 + 测试来源，**真实世界多样性**。
- 生成并保存一份 `split.txt`（哪些 ID 在 train/val/test），保证可复现。

### 步骤 7 · 数据导出 + 版本化
- 导出重建数据集 CSV（含 ID / 类别 / 来源 / 描述 / y1..yn）。
- 纳入版本：建议导出一份带"生成日期+规则版本号"的归档（如 `dataset_20260918_v1.csv`）。
- 导出指标报告：每类 train/val/test 计数、总有效谱数、剔除/UNKNOWN 清单——作为后续 B/C 评估的对照基线。

## 7. 依赖与风险

- **依赖**：参考库 26 条已天然规整（低风险）；实测库 158 条可直接用（避免了"无谱可训"的困境）。
- **风险 1：命名歧义**（PET/PE 前缀、`.` vs `-` 分隔）→ 靠规则顺序 + 人工复核名单兜底。
- **风险 2：类内仍很小**（PMMA 仅 2 条参考 + ~13 条实测）→ 步骤 5 数据增强 / 更多采集。
- **风险 3：网格不统一若强对齐**可能引入插值偏差 → 复用项目既有插值逻辑，并在步骤 4 验证坐标误差。
